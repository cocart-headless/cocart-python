# Next Changelog for CoCart Python SDK <!-- omit in toc -->

> [!WARNING]
> This changelog is **NOT** final. It lists the changes waiting for the next release of `cocart`, to be moved into a changelog under the new version when it's released.

## Changed

- **Retries never send a change twice.** With `max_retries` set, a request that changes something (a POST, PUT or DELETE: placing an order, paying, adding to the cart) is no longer sent again after a timeout or a dropped connection, as it may already have run on the store: a retried checkout could charge the card twice. A 429 is still retried for any request, since the rate limit refuses it before it runs, and a 503 or timeout for a GET.
- **Python 3.11 or later is required.** Python 3.9 and 3.10 are no longer supported: 3.9 reached its end of life in October 2025, and 3.10 does in October 2026.
- **`Response.get_notices()` returns notices keyed by type** (`{"success": [...], "error": [...]}`), which is how CoCart sends them, instead of a list. When there are none it returns `{}` (CoCart Starter 5 sends `{}`, CoCart 4.x `[]`).
- **The client remembers the cart on its own.** It now reads the cart key from its storage adapter (for example `FileStorage`) when it's created. Before, the next run started a new cart unless you called `restore_session()`. A `cart_key` passed to the constructor still takes precedence. A web app serving many customers must not share one storage (or `storage_key`) between them.
- **A guest cart that no longer exists is replaced automatically.** CoCart Starter 5 refuses a cart key with no cart session on every cart route (`cocart_invalid_cart`), for example after the cart expired. The client then forgets the stored cart key and retries the request once as a new guest, so the shopper isn't stuck. A `SessionManager` whose storage the client doesn't share needs the new key saved with `session.set_cart_key(client.get_cart_key())`.
- `Products.sort_by()` takes the `ProductOrderBy` and `SortOrder` literals instead of `str`, so type checkers flag a sort order CoCart rejects.
- **A 409, 429 or 5xx is always a plain `CoCartException`.** Before, one whose code contained `invalid` or `missing` became a `ValidationException`, so a refused state such as `409 cocart_order_invalid_status` read as a form error. A 400 is still a `ValidationException`, and a 401 or 403 an `AuthenticationException`.
- **`request_raw()` emits the `request`, `response` and `error` events** like every other request, so debug output and listeners see the CoCart Plus routes (checkout, account) too, and its error messages name the method and route like the others (`GET /cocart/v2/order-received/12: Not found. [cocart_order_not_found]`). An unexpected transport error becomes a `network_error` without the URL, as elsewhere. It still never sends a request again.
- **`main_plugin` `"basic"` is renamed `"starter"`**, after the CoCart Starter plugin. It's the default and what `get_main_plugin()` returns, and the `MainPlugin` type is now `Literal["starter", "legacy"]`. `requires_basic()` is renamed `requires_starter()`.

## Added

- `Response.get_shipping()` returns the cart's whole `shipping` field: the package count, whether shipping has been calculated, and the packages.
- `Response.get_extensions()` reads the cart's `extensions`, and `Response.get_rate_limit()` the `RateLimit-*` headers (`limit`, `remaining`, `reset`, `retry_after`).
- Methods for the CoCart Plus 2.0 routes the SDK didn't cover: `cart().get_mini()`, `cart().remove_coupons()`, `cart().remove_all_items()` (keeps coupons and fees), `products().shipping_rates()`, `products().create_review()`, and on `account()`: `register()`, `update_address()`, `cancel_order()`, `verify_email()`, `send_order_email_verification()`, `verify_order_email()`, the subscription methods (`get_subscriptions()`, `get_subscription()`, `suspend_subscription()`, `reactivate_subscription()`, `cancel_subscription()`, `set_subscription_auto_renew()`, `update_subscription_payment_method()`, `resubscribe()`, `cancel_resubscribe()`) and `request_order_withdrawal()`.
- `apply_coupon()` and `check_coupons()` take an optional email for coupons restricted to certain emails; `add_fee()` takes an optional tax class.
- `CoCartException.get_cart()` returns the cart sent with an error: `cocart_item_not_in_cart` carries the current cart since CoCart Starter 5.
- **Choices for CoCart Plus's supported plugins.** `add_item()`'s options are documented for a subscription plan (`convert_to_sub`), a gift recipient (`recipient_email`) and a warranty (`item_data={"warranty": ...}`); other plugins' fields still pass through. `cart().change_plan(item_key, value)` switches a cart item to another plan, or to one-time with `"0"`.
- `request_raw()` takes `omit_cart_key=True` for routes that refuse a cart key.
- `docs/extension-data.md` lists the data CoCart Plus adds under `extensions` for the plugins it supports, and how to send the customer's choices.
- **Checkout (CoCart Plus 2.0).** `client.checkout()` places orders and takes payment: `place_order()` with `payment_data` as a dict of the keys the gateway reads (`{"wc-stripe-payment-method": "pm_…"}`: gateway tokens only, never card numbers), and a free order needs neither `payment_data` nor `payment_method`. It returns a `CheckoutResult` read from the response's `result`: `code` (`order_placed`, `action_required`, `payment_pending`, `payment_failed`, or `payment_method_changed` for a subscription), `is_complete()`, `is_awaiting_payment()` (placed, but the customer still pays: Stripe wallets and vouchers, BLIK, bank transfer…), `needs_confirmation()` for 3D Secure, `needs_redirect()` for an off-site step, `is_pending()`, `is_failed()`, and `object`, `order_id`, `order_key`, `order_number`, `order_status`, `subscription_id`, `redirect_url` (https or http only), `client_secret`, `intent_type`, `payment_method_type`, `message`, `error_code`, `gateway_error_code`, `gateway_message`, `action_type`, `action_data` and `response`. A declined card is a result to read, not an exception, and printing a result never shows `client_secret` or `order_key`. `pay_for_order()` (which sends the order key in the body) and `confirm_return()` return the same result. Also `get()` (with optional `currency`, `formatted` and `thumb`; call it on the review page, since CoCart Plus refuses an order whose total changed since, `409 cocart_checkout_total_mismatch`), `update()` (what it couldn't apply is in `result.not_applied`), `process()`, `get_config()`, `get_payment_methods()`, `get_saved_payment_methods()` (each with `id`, `gateway_id`, `label` such as "Visa ending in 4242", `type`, `expires`, `is_default` and `supports_subscriptions`), `search_addresses()`, `get_address_details()`, `get_order_received()` (with optional `formatted` and `meta_keys`) and `confirm_order_payment()`. See `docs/checkout.md`.
- **Checkout: finding out how an order ended when no answer came back.** `place_order()` sends each order with a random `checkout_id`, or yours in the data (16 to 64 letters, digits, `-` or `_`; anything else is a `ValidationException` `checkout_invalid_checkout_id` before anything is sent). When the connection drops, the request times out, a proxy gives up waiting, or another request is still taking payment for the cart (`409 cocart_payment_in_progress`), it raises `CheckoutOutcomeUnknownException` (a `CoCartException`) with `checkout_id`, and `checkout().get_status(checkout_id)` asks CoCart Plus 2.0 how the checkout ended: `code` is `order_placed`, `payment_required` (pay it with `pay_for_order()`), `in_progress` or `not_placed`, with `message`, `order_id`, `order_key`, `order_number` and `order_status`.
- `account().update_subscription_payment_method()` takes a new card in `payment_data` as well as a saved card's `token_id`, and returns a `CheckoutResult` (`object` `subscription`, `code` `payment_method_changed` once changed), since a new card may need 3D Secure.
- `account().get_orders()` filters by `status` (one or a list), `after`, `before` and `subscription_order_type`, and `get_subscriptions()` by `status`. `get_profile()`, `get_orders()`, `get_order()`, `get_guest_order()`, `get_subscriptions()` and `get_subscription()` take optional `formatted` and `meta_keys`. A list is sent comma-joined and a boolean as `true` or `false`.
- `CoCartException.get_fields()` returns every field at fault, by path, with its message (CoCart Plus checks a whole form at once), `get_field()` the first one and `get_reason()` the underlying plugin's own reason.
- The `response` event carries the `Response` as `response`.

## Fixed

- **`Response.get_shipping_methods()` returned the whole `shipping` field instead of the packages.** CoCart sends shipping packages keyed by package ID under `shipping.packages`; `get_shipping_methods()` now returns them as a list.
- **`apply_coupon()` was rejected by CoCart Plus** because it sent the code as `coupon` instead of `code`. The batch example in `docs/cart.md` made the same mistake.
- **`add_fee()` was rejected by CoCart Plus** because it sent the amount as a number; the route takes a string.
- **`Response.get_fees()` returned the fees keyed by fee ID instead of a list.** It now returns them as a list.
- **`account().change_password()` and `get_reviews()` called routes CoCart Plus doesn't have.** The password now goes to `POST /my-account` (`password_current`, `password_1` and `password_2`), and reviews come from `products/reviews/mine`.
- **`remove_coupon()` broke for coupon codes with spaces, `%`, `#` or `?`.** The code went into the URL unencoded. It's now encoded.
- **`ProductOrderBy` allowed `"price"`, which CoCart rejects.** It now lists the sort orders CoCart accepts: sort by price with `price_asc` or `price_desc`. `menu_order`, `name`, `alphabetical`, `reverse_alpha`, `sales`, `review_count`, `by_stock`, `on_sale_first` and `featured_first` were missing, and `relevance` and `rand` work with CoCart Starter. The docs sorted by `price` too.
- **Error messages included the full request URL**, which can contain the cart key and API credentials. They now name only the route, e.g. `POST /cocart/v2/cart/add-item: Product not found. [cocart_product_not_found]`.
- **A 429 from CoCart Plus was retried on the default backoff** instead of after the wait it asked for: the client read only `Retry-After`, and CoCart Plus sends `RateLimit-Retry-After`. It now reads `RateLimit-Retry-After`, then `Retry-After`, up to 60 seconds.
- **Debug output logged the full request URL**, whose query string can carry the cart key, an order key or an email address. Every query value is now shown as `***`. The events still carry the full URL: don't forward it to logs or analytics as it is.
- **The ETag cache kept responses marked `Cache-Control: no-store` or `private`**, such as a customer's checkout, orders and account from CoCart Plus. They're no longer kept.
- **Connection error messages included the cart key.** `requests` puts the request URL, query string included, in its connection errors, and the SDK passed that message on and chained the original exception. The query string is now removed, and the original exception is no longer chained.
- The docs read product prices from `price` and the product list as a plain list. Prices are under `prices` (minor-unit strings) and the list is under `products`.
- `docs/sessions.md` said a `SessionManager` restores the stored cart key on the next request; only the client does that, when it has the same storage.
